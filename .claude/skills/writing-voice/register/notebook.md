# The notebook voice, in brief

Read with `exemplars/notebook.md`, never instead of it. The voice is the technical description's register (`register/td.md`) applied to the parts a teaching notebook has, and the conventions below are the series' own, stated in `AGENTS.md`'s notation section, in full in `CANON.md`, and in the nodal market fundamentals notebook, published in an earlier version of this repository (commit ce66306), the tested notebook (user decision 2026-10-12).

A notebook states its math before it clears anything. The formulation opens with the nomenclature table, `| Symbol | Code | Definition |`, which maps every symbol the notebook uses to the object's name in the shared libraries and to a definition in words (NB-03). The program is then stated whole, an objective subject to its constraint families with each family's dual in brackets, and numbered from (1) in that notebook alone (NB-04). Every numbered display equation is followed by an `*In words.*` blurb that reads the equation left to right in the equation's own order, names each quantity by its table name with the symbol inline ("the absolute shadow price $|\mu_m|$ times the absolute flow $|F_m|$"), and says what a symbol is before using it (NB-04, NB-05, NB-07). The blurb may keep the "subject to three constraint families: A (dual X); B (dual Y); C (dual Z)" shape because it mirrors the equation, and it is the only labelled construct a notebook carries. A mechanical consequence the reader might miss opens with "Note that" (NB-05).

The prose under an output reads the number and stops: which line bound, which price moved and to what, what resetting the knob does (NB-09). There is no marker and no lead-in. A section that tightens a construct already stated says so in its first sentences and names the earlier equation by its number in this notebook (NB-10). A mechanism is explained in plain declaratives on a concrete case, with the numbers in the sentence (NB-11). The sandbox and the configuration view are introduced by saying what they hold and what they are not (NB-12, NB-13). A sibling is named by file, as in "`101_sandbox.ipynb` reruns the same chain", and never by its section or equation numbers, because those renumber.

The canon governs the symbols: the line index is $m$, the shift factor is $SF_{n,m}$ bus first, $\mu_m$ is signed with $+\sum SF\mu$, $N_a^c$ is the congestion by region and $N_a$ the net position, the interface set is script $\mathcal I$. Math is `$…$` and `$$…$$`, never `\(…\)`, because the VS Code preview renders only the former.

One contrast. The mannered writer produces "a physical picture of where power prefers to flow before any dispatch is chosen" (that notebook's cell 8, not an exemplar); the voice produces "The shift factors build each engine's flow $F^M_m=\sum_n SF_{n,m}\,p^{\text{inj},M}_n$" (its cell 6). The first gives the network a preference; the second names the quantity.
